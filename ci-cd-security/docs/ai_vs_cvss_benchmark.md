# AI v4 Model vs CVSS Baseline

## Purpose

This benchmark compares VulnPriority's final single v4 AI model with a CVSS-only baseline. CVSS remains useful as a general severity score, but it does not directly rank findings by the operational priority learned from the project dataset.

The single v4 model uses vulnerability metadata, text-derived indicators, CWE tiers, package information, scanner context, timing features, and reference/advisory features to produce a prioritization signal for triage.

## Compared systems

| System | Sorting / decision basis |
|---|---|
| Single v4 AI model | `ai_probability` and `ai_risk_score` generated by the stacked model |
| CVSS baseline | CVSS threshold rules, especially CVSS >= 9.0 |

## Main result

The final stacked model outperforms the CVSS-only baseline on the same held-out test set.

| Metric | Single v4 AI model | CVSS baseline >= 9.0 |
|---|---:|---:|
| Precision | 0.7098 | 0.4049 |
| Recall | 0.5957 | 0.4348 |
| F1 | 0.6478 | 0.4193 |
| F1-macro | 0.7929 | 0.6507 |
| ROC-AUC | 0.9056 | 0.7847 |
| AUC-PR | 0.7387 | N/A |

The dashboard uses the balanced default threshold of `0.386`. A lower high-recall threshold is documented for situations where catching more high-risk vulnerabilities is more important than reducing false positives.

## Why the AI model is better than CVSS alone

CVSS is useful but static. It does not directly model whether a finding is likely to be operationally important in this dataset. The AI model adds signals such as:

- advisory references;
- publication and modification timing;
- reference counts;
- package metadata;
- CWE exploitability tier;
- vulnerability text length and keyword features;
- scanner type and source context.

These signals allow the model to learn triage patterns that CVSS alone cannot represent.

## Responsible interpretation

The AI output should not replace analyst judgment. It should be used as a prioritization layer:

1. Use AI score and probability to sort the review queue.
2. Keep scanner severity and CVSS visible.
3. Prioritize high AI score plus high scanner severity findings first.
4. Review low-confidence cases manually.
5. Treat the model as decision support, not as an automatic patch/no-patch decision.
