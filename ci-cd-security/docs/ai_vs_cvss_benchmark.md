# AI v4 Model vs CVSS Baseline

## Purpose

This benchmark compares VulnPriority's final single v4 AI model with a CVSS-only baseline. CVSS is useful, but it is a general severity score. The AI model combines additional vulnerability metadata, text-derived indicators, CWE tiers, package information, scanner context, and temporal/reference features to produce a prioritization signal for triage.

## Compared systems

| System | Sorting / decision basis |
|---|---|
| Single v4 AI model | `ai_probability` / `ai_risk_score` generated by the stacked model |
| CVSS baseline | CVSS threshold rules, especially CVSS >= 9.0 |

The default threshold is `0.386`. It gives the best balanced result for the dashboard. A lower high-recall threshold is documented for situations where catching more high-risk vulnerabilities is more important than reducing false positives.

## Why the AI model is better than CVSS alone

CVSS is useful but static. It does not directly model whether a finding is likely to be operationally important in a specific vulnerability dataset. The AI model adds signals such as:

- advisory references,
- publication and modification timing,
- reference counts,
- package metadata,
- CWE exploitability tier,
- vulnerability text length and keyword features,
- scanner type and source context.

These signals allow the model to learn triage patterns that CVSS alone cannot represent.

## Responsible interpretation

The AI output should not replace analyst judgment. It should be used as a prioritization layer:

1. Use AI score/probability to sort the review queue.
2. Keep scanner severity and CVSS visible.
3. Prioritize high AI score + high scanner severity findings first.
4. Review low-confidence cases manually.
5. Treat the model as decision support, not as an automatic patch/no-patch decision.
